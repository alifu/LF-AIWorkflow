The quick overview of the project is simple: a small notch application watches a terminal session, collects the output, and shows the user a short summary of what happened. When a build fails, the application scans the log for the first error, includes a few lines of context, and offers to send that excerpt to the assistant. Because every request costs tokens, the application estimates the size of each message before it is sent, so that people can decide whether to trim the context first.

Designing such an estimator is a trade-off. A precise tokenizer needs large vocabulary tables and is slow, while a rough heuristic is fast and tiny but can drift on unusual text. The goal here is not perfection; it is a number that is close enough to be useful, produced in a single pass over the bytes, without allocating any memory. In practice, English words average a little over one token each, long identifiers split into several pieces, and punctuation usually costs one token per mark.
